# Fable 5.1 review of W0: the reconciled Mage Arena design

Reviewer: Claude Fable 5.1, independent, no code changes. Date: 2026-10-02.
Scope: `docs/design/reconciled/` (README, data, fixtures, defects.json) and the
replayer in `packages/tools/replay/`, checked against the owner direction and
sections d and f of `docs/MAGE-ARENA-PLAN.md` and the defect list in
`docs/judging/fable-verdict.json`. Reviewed at commit `cd29a21` plus the
uncommitted working tree on branch `core`.

## Verdict

**Accepted for handover, with six fixes owed.** The tables are one authority, the
golden nights are generated by the replayer and every delta I recomputed by hand
is derivable from the data files, loops are gone from the active data, the
season calendar is in data and produces six Games and six eve Trials, and the
death reservation matches plan section d. Nothing I found blocks a coding agent
from building W1 on these tables. What survives is residual: one archived place
name and one archived verb vocabulary inside `goals.json`, two intents with no
place, an output schema the package describes but does not ship, and a checker
whose "zero contradictions" claim is narrower than the gate text implies. None
of these changes a number in a fixture.

## Defects

Ranked by how much they would cost a coding agent. File paths are repo-relative.

1. **`docs/design/reconciled/data/goals.json:6`: the Well is still referenced.** The plan string for `escape_research` reads "study at well; socialize(quill); plot". `locations.json` has no well, `defects.json:25` marks `missing-well` fixed, and the checker's obsolete-data regex at `packages/tools/replay/check.mjs:39` matches only capitalised `Well`, so the lowercase reference passes (my probe 2 confirmed a planted lowercase "well" also passes). Fix: rewrite the string to the Cistern and make the regex case-insensitive.

2. **`docs/design/reconciled/data/goals.json:2-16`: a second verb vocabulary survives in active data.** The fifteen plan strings use the Ledger's activity words (`socialize`, `help`, `scout`, `trade`, `study`, `pit_challenge`) alongside words that happen to match intents (`train`, `scheme`, `report`, `plot`, `recruit`, `work`, `rest`). Only the goal ids are used by the replayer; the strings are free prose. A coding agent writing the planner will read them as a specification and find six verbs that do not exist. Fix: either rewrite each plan as a list of closed-vocabulary intents with args, or mark the field as flavour and move it out of the data directory.

3. **`docs/design/reconciled/data/locations.json`: two intents have no place and one activity is not an intent.** `SCHEME` and `DEFECT` appear in no location's `activities`, while the Pit lists `trial` (line 33), which is not in `intents.json`. The replayer ignores places entirely, so the fixtures are unaffected, but W5 (season map, time slots) will have to invent where a scheme happens. The checker does not validate activity tokens (my probe 4: a planted `ASSASSINATE` activity passes). Fix: add the two intents to places, and either add a `trial` event type or move the Trial to `season.json` only.

4. **`docs/design/reconciled/README.md:33` and the package as a whole: the Director output schema is described but not shipped.** The README says decisions "explicitly name their resolution calendar day in the request", yet no item in `fixtures/golden-nights.json` carries a day, and the reconciled package contains no JSON Schema for a decision or a group call. The only schema is the archived baseline's `director-schema.json`. Section f item 2 asks that worked nights "validate against the schema"; W0 cannot do that against a schema it does not own. The W1 working tree generates one from the tables (`packages/director/src/schema.ts`, uncommitted), which is the right shape, but the design package should carry the authoritative one. Fix: add `data/decision.schema.json` (or generate it into the package) and either add the day to the item or move that sentence to describe the request envelope.

5. **`docs/design/reconciled/defects.json:19` contradicts `README.md:40-41` on what a scheme records.** The defect entry says the actor's "last executed scheme" is recorded; the README says "last attempted target". The replayer (`packages/tools/replay/reference.mjs:200` at `cd29a21`) records every resolved attempt, success or failure, and a rejected or capped item never resolves, so it is never recorded. The README is right; the defect entry's wording is wrong. One-word fix.

6. **`docs/design/reconciled/README.md:14-29`: the scheme window is enforced but not stated.** `season.json:7` sets `schemeOpensWeekday: 4`; the validator rejects earlier schemes with reason `scheme-window`, and the fixtures depend on it (night 1 is weekday 4, exactly on the boundary; my probe 6 moved the window to weekday 5 and the fixtures failed). The data-derived contract in the README does not mention it. Add one template line.

Lower-severity observations (no fix required for W1, record for W11 balance and W10):

7. **`docs/design/reconciled/data/rules.json:150-181`: a rumour-monger reacts to their own rumour.** On the Games-eve night Kesh spreads `serves_rome` about Sadruba and the trace shows `trust/kesh>sadruba` falling by 10 along with Iskar, Lio and Corvo. The listener filter at `reference.mjs:216` excludes only the target. The fixture is correct for the data; the data is probably not what the designer meant.

8. **Balance: a rumour against a renown-5 target cannot fail for guile 3 or higher.** DC is `rumourBaseDc` 12 plus renown/10 = 12; score is guile x 4 plus d20, so Nysa's night-1 rumour succeeded on a natural 1 (fixture roll value 1, score 13). Authored, not a contradiction, but it means the first week's rumours are automatic.

9. **Balance: `PROTECT` on a fed target is a flat +10 trust and a debt.** Night 2: Garran protects Cassia at hunger 0; the hunger delta clamps to nothing, the trust and debt still land. With Earth weighting `PROTECT` at 1.5 this is a cheap trust engine.

10. **`docs/design/reconciled/data/characters.json:673, 722`: schools `salt` and `none` have no row in `schools.json`,** and the checker has no school foreign key. My probe 3 (an unknown school on a main) was caught only because routine training reads the school and the fixture replay then diverged. Add the check or add the rows.

11. **Fixture coverage is narrower than the vocabulary.** Across the three nights only `PROTECT`, `BEFRIEND`, `WORK`, `REST`, `WATCH` and `SCHEME` (rumour, poison, steal) resolve. `TRAIN`, `CONFIDE`, `RECRUIT`, `DEFECT`, `REPORT`, `PLOT`, `OFFER`, the persuade scheme, the caught branch, the `stocks` state, a `lineReplaced` repair and a Games day never appear in a golden night. The W0 gate asked for three nights and got them; W1 should add scenarios so its oracle covers every verb once.

12. **Checker claim versus checker reach.** The W0 card says the checker "finds zero contradictions between prose, tables and fixtures". It checks that the README equals the rendered template, foreign keys for goals, facts, values, relationships and calendar places, phrase lines, obsolete loop fields, the death flag, exact fixture replay and rule-reference resolvability. It does not check free prose against code: my probe 1 changed "higher cunning" to "lower cunning" in both template and README and the checker returned no errors. `README.md:75-76` says this honestly; the wave card and `W0-report.md` should use the README's wording.

13. **Working tree note for the orchestrator.** `packages/tools/replay/reference.mjs` is uncommitted-modified to a two-line re-export of `packages/core/src/camp.ts` (W1 in progress). The `check` command as run today therefore exercises W1 code. I ran the committed `cd29a21` reference and the W1 adapter side by side: both reproduce the stored fixture byte for byte (237 deltas). The W0 package at HEAD is self-contained; the working tree is not.

14. **Naming: `PLOT` intent versus the death-system `Plot` object.** The W0 note defines `PLOT` as nonlethal bond planning and `death-reservation.json` sets `deathIntent: null`, so there is no ambiguity in data, but a coding agent reading plan section d next to `intents.json` will trip on it. Consider renaming the intent (`CONSPIRE` or `MEET`) before W10.

## Summary

1. Verdict: W0 is accepted for handover; section f items 1 to 5 are closed in substance, with residue in `goals.json` (well, Ledger verbs) and a missing output schema.
2. All seventeen deltas I recomputed by hand across the three golden nights match the tables, and the committed replayer, the W1 adapter and the stored fixture agree byte for byte.
3. Season data is complete (six Games, six eve Trials, slots, endings) and no loop, Echo or ring-reset field remains in active data or prose.
4. The death reservation matches plan section d on stages, fields, ceilings and the no-kill-verb rule; W10 still owes the Vigil-stage cost roll, the crackdown cap field and the Trial-versus-window clash.
5. Owed before anyone relies on them: fix `goals.json`, place `SCHEME` and `DEFECT`, ship the decision schema, align the two scheme-recording sentences, state the scheme window, and widen the checker's regex and foreign keys.
